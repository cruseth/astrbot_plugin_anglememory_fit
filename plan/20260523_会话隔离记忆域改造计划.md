# 会话隔离记忆域改造计划

## 背景

当前 `conversation_scope_map` 的行为是：

- 先用当前人格名匹配记忆域。
- 再用 `event.unified_msg_origin` 会话 ID 匹配记忆域。
- 未命中时返回 `public`。

这会导致未配置的会话默认共享公共记忆，不符合“默认按会话窗口隔离，部分会话显式共享同一份记忆”的目标。

## 目标

1. 默认每个会话窗口使用独立记忆域。
2. 管理面板里可以配置若干会话窗口共享同一个记忆域。
3. 保留旧配置的基本兼容能力，但不再让人格名默认造成跨会话共享。
4. 插件改名为 `astrbot_plugin_angel_memory`，更新仓库地址为 `https://github.com/cruseth/astrbot_plugin_anglememory_fit`。
5. 完成后推送到用户仓库。

## 推荐方案

### 1. 新的记忆域解析策略

新增一个明确的配置组，例如 `memory_scope`：

```json
{
  "strategy": "per_conversation",
  "shared_scopes": {
    "aiocqhttp:group:12345": "family",
    "aiocqhttp:private:10001": "family",
    "aiocqhttp:group:67890": "work"
  },
  "legacy_public_scope": false
}
```

解析规则：

1. 读取当前事件的 `event.unified_msg_origin`。
2. 如果该会话 ID 在 `shared_scopes` 中，则使用配置的共享 scope。
3. 如果未命中：
   - 默认使用该会话自己的私有 scope。
   - scope 由会话 ID 稳定生成，例如 `session_` + `sha1(unified_msg_origin)[:16]`。
   - 不直接用原始会话 ID 作为 scope，因为原始 ID 常包含冒号等字符，而现有 scope 校验只允许字母、数字、中文、下划线、短横线。
4. 仅当用户显式打开 `legacy_public_scope` 时，才恢复旧版未命中 `public` 的行为。

这样可以保证默认隔离，同时允许多个会话通过相同 scope 名共享记忆。

### 2. 旧配置兼容

保留 `conversation_scope_map` 的读取，但降级为兼容入口：

- 如果新配置 `memory_scope.shared_scopes` 存在，优先使用新配置。
- 如果新配置不存在，但旧 `conversation_scope_map` 存在，则读取旧配置作为会话 ID 映射。
- 不再默认用人格名优先匹配，避免同人格的多个会话自动共享记忆。
- 日志里提示旧配置字段已兼容读取，建议迁移到新配置。

如果确实需要“按人格共享”，后续可以再加单独开关，但本次不默认启用。

### 3. AstrBot WebUI 适配

优先用 AstrBot 原生 `_conf_schema.json` 做配置，不先写复杂独立面板：

- `memory_scope.strategy`：下拉框，默认 `per_conversation`。
- `memory_scope.shared_scopes`：JSON 编辑器或表单化对象，用来配置“会话 ID -> 共享记忆域”。
- `memory_scope.legacy_public_scope`：布尔开关，默认关闭。

同时保留当前启动后“每个会话只打印一次会话 ID”的日志提示，并把提示文案改成新格式，例如：

```json
{
  "aiocqhttp:group:12345": "family"
}
```

这已经能直接在 AstrBot 插件配置界面修改，成本低，稳定性更高。

## 代码改动范围

1. `core/plugin_context.py`
   - 新增安全 scope 生成函数。
   - 新增 `memory_scope` 配置读取和校验。
   - 调整 `resolve_memory_scope_with_source()`：共享映射优先，未命中默认会话隔离。
   - 刷新配置时同步刷新新旧映射。

2. `core/config.py`
   - 读取并导出 `memory_scope` 配置。
   - 保留 `conversation_scope_map` 兼容字段。

3. `_conf_schema.json`
   - 新增 `[记忆隔离]` 配置组。
   - 将旧 `[记忆分类] conversation_scope_map` 标记为兼容配置或隐藏/弱化说明。

4. `main.py`
   - 更新注册信息中的仓库地址、版本号。
   - 更新会话提示日志，说明默认隔离和共享映射写法。

5. `metadata.yaml`
   - `name` 保持或改为 `astrbot_plugin_angel_memory`。
   - `repo` 改为用户仓库。
   - 版本号至少递增一位。

6. `README.md`
   - 更新安装仓库地址。
   - 更新记忆隔离配置说明。
   - 说明从旧 `conversation_scope_map` 迁移到新 `memory_scope.shared_scopes` 的方式。

7. 测试
   - 新增或更新单元测试覆盖：
     - 未配置会话默认生成私有 scope。
     - 两个会话配置到同一 scope 后共享。
     - `legacy_public_scope=true` 时未命中回到 `public`。
     - 旧 `conversation_scope_map` 可兼容读取。
     - 非法 scope 被忽略并记录警告。

## 推送计划

实现完成并通过测试后：

1. 将目录整理为 `astrbot_plugin_angel_memory`。
2. 初始化或绑定 Git 仓库。
3. 设置远程仓库为 `https://github.com/cruseth/astrbot_plugin_anglememory_fit`。
4. 提交 Conventional Commit，例如 `feat(scope): 默认按会话隔离记忆域`。
5. 推送到用户仓库。

推送前需要确认当前目录不是 Git 仓库这一点是否符合预期；如果用户希望保留现有 `angel_memory` 目录，我会在原目录内初始化并改远端，否则会复制/整理到同级 `astrbot_plugin_angel_memory` 目录。

## 风险与处理

- 历史 `public` 记忆不会自动迁移到每个会话私有 scope。本次只改变新写入和检索策略；已有 `public` 仍会作为公共记忆被私有 scope 检索到，因为底层当前允许私有 scope 同时读取 `public`。
- 如果用户希望彻底隔离到“不读 public”，需要额外调整底层检索规则，这属于更强隔离模式，建议单独加开关。
- 直接内置复杂 WebUI 会增加维护面，建议先用 AstrBot 原生配置 schema 实现可配置能力，验证稳定后再补轻量页面。
